1. FONCTION
Ce document conserve uniquement les lecons utiles avant suppression des anciennes sources.
Il n'est pas une source de verite statistique.
Il sert a orienter les backtests Document 11 et a empecher la repetition des biais observes.

Document 4 ne selectionne jamais un cheval.
Document 4 ne valide jamais un ticket.
Document 4 ne modifie jamais une regle active sans passage par Document 11, Document 10, Document 3, Document 2, Document 0 et Document 1.

2. STATUT
Priorite basse.
Aucune observation ci-dessous ne valide un ticket.
Toute hypothese doit etre testee dans la base CSV + SQLite et confirmee par :
- decision_engine_outputs rejouable ;
- split hors echantillon valide ;
- leakage_check_ok = true ;
- ROI reel segmente ;
- erreur proxy maitrisee ;
- arbitrage CP_SEC vs CP3 ;
- calibration SP independante si SP standard ;
- replay_match controle ;
- proba_basse calibree.

Une bonne arrivee post-course ne transforme jamais une observation en regle.

3. VERROUS ISSUS DU RETOUR UTILISATEUR
- decision_engine_outputs devient prioritaire : une decision non rejouable reste fragile ou exclue du strict.
- input_hash, engine_version et ruleset_version doivent permettre de rejouer le meme verdict.
- train_test_split devient bloquant : TRAIN calibre, VALIDATION controle, TEST_LIVE audite.
- leakage_check_ok = false exclut la ligne du KPI strict.
- Proxy_error_by_segment.csv reste prioritaire : un segment qui surestime regulierement les rapports reels doit etre degrade ou refuse.
- CP_SEC vs CP3 reste prioritaire : CP3 n'est pas la structure reflexe ; une paire dominante doit etre testee en CP sec.
- SP standard exige sp_calibration_segments UTILISABLE ; sinon micro-SP 1 EUR max ou simulation.
- ROI reel, hors doctrine, simulation et paper trading ne doivent jamais etre fusionnes.
- ROI global flatteur est invalide.
- Historique utilisateur = discipline de jeu, jamais calibration publique.

4. BIAIS A NE PLUS REINTRODUIRE
- Transformer un regret en ticket.
- Utiliser un favori sous-paye comme base par confort.
- Jouer un CP3 avec une seule vraie paire.
- Jouer un CP3 quand le CP_SEC couvre mieux l'exposition.
- Confondre ticket qui touche et ticket rentable.
- Jouer un exotique parce que la lecture sportive est correcte.
- Ajouter un reducteur pour sauver une analyse faible.
- Surponderer presse, top driver, deferrage, steam ou cote haute isoles.
- Refaire l'analyse pre-course avec l'arrivee connue.
- Melanger STRICT, MICRO-SP, SP, CP_SEC, CP3, HORS_DOCTRINE, SIMULATION ou PAPER_TRADING dans un ROI global.
- Utiliser un segment proxy surestime comme edge net.
- Utiliser une decision sans input_hash comme preuve.
- Valider une regle sans split hors echantillon.
- Valider un SP standard sans segment_SP UTILISABLE.
- Transformer un micro-SP gagnant en doctrine SP standard.
- Utiliser l'historique utilisateur pour recalibrer C_prudent.
- Conserver un CP3 positif uniquement grace a un gros retour isole.
- Presenter un CP3 remboursant comme edge.

6. LECONS DE PERTES RECURRENTES
Les pertes observees viennent principalement de :
- profil fautif integre au panier ;
- favori sous-paye utilise comme base ;
- micro-SP trop speculatif ;
- SP value sans calibration suffisante ;
- CP3 avec une seule paire reelle ;
- CP3 inferieur au CP_SEC ;
- CP3 seulement remboursant ;
- exotiques joues pour couvrir une incertitude ;
- absence de mesure d'erreur proxy ;
- volatilite SG tardive sous-estimee ;
- decision post-course reinterpretee comme preuve ;
- ticket utilisateur hors doctrine confondu avec validation GPI.

7. LECONS DE REGRETS UTILES
Profils a surveiller en backtest, jamais a jouer automatiquement :
- forme pure + J/E positif ;
- chevaux premier poteau dans grands lots ;
- ancre top4 sous-payee mais fiable ;
- duo propre ou CP_SEC aurait mieux couvert que CP3 ;
- SP 3-5 avec forme propre, marche coherent et segment_SP UTILISABLE ;
- outsider proche du top marche avec ligne recente solide ;
- favori faible pouvant etre remplace par une paire CP_SEC plus couverte ;
- profil steam fort mais fautif, uniquement si cela ne cree pas deux fautifs dans un panier ;
- cheval refuse car SP bas mais utile en CP via SG, a tester seulement par proxy.

10. REGLE DE PROMOTION D'UNE LECON
Une lecon Document 4 peut devenir candidate de regle seulement si :
- elle est traduite en variable mesurable ;
- elle est testee hors echantillon ;
- elle dispose d'au moins 30 a 50 cas selon le segment ;
- le ROI median n'est pas negatif ;
- le drawdown est acceptable ;
- le replay_match est controle ;
- le segment proxy ou SP n'est pas ROUGE/ND ;
- la performance ne depend pas d'un seul gros retour ;
- le tracker Document 3 valide le niveau de preuve.
