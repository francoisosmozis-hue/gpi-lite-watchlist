2. PRINCIPE NON NEGOCIABLE
Le rapport CP exact ne peut pas etre calcule depuis les seules cotes SG.
Le CP est mutualise. Liquidite, mises par combinaison, arrondis, compression des favoris et biais de pool modifient le rapport.

Methode autorisee :
SG ZEturf -> p_i normalisees -> P_event_market -> C_prudent -> R_prudent.

Interdits :
- R = 1 / P brut comme validation ;
- somme des cotes SG comme validation ;
- cote PMU/Geny utilisee dans l'EV ZEturf ;
- rapport calcule sur partants declares au lieu de partants reels ;
- proxy sans segment_id, sample_n, fallback et statut ;
- decision stricte sans calibration_version.

3. NORMALISATION SG
Pour chaque partant reel i :
q_i = 1 / SG_i
M = somme(q_i) sur partants reels hors NP
p_i = q_i / M

Regles :
- NP retires avant normalisation ;
- disqualifies conserves comme partants reels ;
- SG absente, nulle ou incoherente = calcul invalide ;
- partants declares utilises a la place des partants reels = calcul invalide ;
- toute normalisation doit conserver source_snapshot_time.

Fonction standard :
normalize_sg(runners)
Entrees :
numero, cheval, SG, statut_NP
Sorties :
numero, SG, q_i, p_i, rang_marche

Controle :
somme(p_i) doit etre proche de 1.
Si ecart > 0,001 apres arrondi interne, sortie invalide.

4. PROBABILITE DE MARCHE PAR PLACKETT-LUCE
Le modele standard GPI pour les probabilites d'evenement est Harville / Plackett-Luce.

Pour une permutation ordonnee top k :
P(ordre r1, r2, ..., rk) =
p_r1
x p_r2 / (1 - p_r1)
x p_r3 / (1 - p_r1 - p_r2)
...
x p_rk / (1 - somme p deja selectionnes)

Fonction standard :
prob_ordered_top_k(order, p)

Regles :
- k = 3 pour CP ;
- k = 4 pour 2sur4 ;
- la probabilite des evenements desordre se calcule en sommant les permutations ordonnees compatibles ;
- si implementation complete absente, la sortie est simulation ou edge fragile.

5. PROBABILITE EVENEMENT CP
CP : deux chevaux doivent finir dans les 3 premiers, desordre.

P_pair_top3(i,j) =
somme des probabilites de toutes les permutations top3 qui contiennent i et j.

Fonction standard :
compute_pair_top3_probability(i, j, p)

Pseudo-code :
P = 0
pour chaque permutation ordonnee de 3 chevaux distincts :
    si i et j sont dans la permutation :
        P += prob_ordered_top_k(permutation, p)
retourner P

Controle :
course admissible CP si partants_reels >=8.
Si partants_reels <8 : CP interdit.

6. PROBABILITE EVENEMENT 2SUR4
2sur4 : deux chevaux doivent finir dans les 4 premiers, desordre.

P_pair_top4(i,j) =
somme des probabilites de toutes les permutations top4 qui contiennent i et j.

Fonction standard :
compute_pair_top4_probability(i, j, p)

Controle :
course admissible 2sur4 si partants_reels >=10.
Si partants_reels <10 : 2sur4 interdit.

7. COEFFICIENTS CP / 2SUR4
C_observe = Rapport_officiel_ZEturf x P_event_market
C absorbe TRJ, liquidite, arrondis, compression favori/outsider et biais de pool.

C_prudent = quantile prudent par segment.
R_prudent = C_prudent / P_event_market.

Erreur_proxy = Rapport_officiel - R_prudent.
Erreur_relative = (Rapport_officiel - R_prudent) / R_prudent.
Surestimation_proxy = R_prudent > Rapport_officiel.
Ratio_reel_proxy = Rapport_officiel / R_prudent.

Lecture :
- erreur_proxy > 0 : proxy conservateur ;
- erreur_proxy < 0 : proxy surestime le rapport ;
- ratio_reel_proxy < 1 : rapport reel inferieur au proxy ;
- surestimation recurrente = segment a degrader.

Fonctions standard :
compute_C_observe(rapport_officiel, P_event_market)
compute_R_prudent(C_prudent, P_event_market)
compute_proxy_error(rapport_officiel, R_prudent)

Regle :
P_event_market <=0 ou C_prudent absent = R_prudent ND.

9. STATUTS PROXY
Statut | Conditions | Usage
VERT | sample_n >=50 ; taux_surestimation <=35 % ; erreur_relative_mediane >=0 ; leakage_check_ok = true | Decision standard possible si autres criteres OK
ORANGE | sample_n >=50 ; taux_surestimation 35-45 % ou erreur_relative_mediane entre -10 % et 0 % | Edge fragile ; CP_SEC prioritaire ; CP3 tres limite
ROUGE | taux_surestimation >45 % ou erreur_relative_mediane < -10 % | Segment degrade ; CP/CP3 reel interdit
FRAGILE | sample_n 10-49 | Simulation ou exception documentee ; jamais edge net
ND | sample_n <10 ; proxy absent ; fallback non declare ; calibration_version absente | Aucun ticket reel

Regles :
- VERT autorise l'etude, pas le ticket automatique.
- ORANGE impose prudence, mise minimale, CP_SEC avant CP3.
- ROUGE interdit le reel strict.
- FRAGILE interdit edge net.
- ND = NO BET strict ou simulation.

Fonction standard :
classify_proxy_status(sample_n, taux_surestimation, erreur_relative_mediane, fallback_declared, calibration_version, leakage_check_ok)

13. CALIBRATION SP INDEPENDANTE
Le SP est une structure distincte du CP, du CP3 et du 2sur4.
Il doit etre calibre par SP visible, resultat place et rapport officiel SP.

Top_paid_places :
- 4 a 7 partants reels : top 2 paye ;
- 8 partants reels et plus : top 3 paye.

Tranches SP :

Fonctions standard :

compute_sp_roi(rapport_SP_officiel, mise_reference)

Seuil theorique :
proba_basse > 1,20 / SP_min

Ce seuil est necessaire mais insuffisant.

Statuts segment SP :
UTILISABLE : sample_n >=30 ; ROI_median >=0 ; ratio_median acceptable ; drawdown_max acceptable.
FRAGILE : sample_n 10-29 ou variance elevee.
REJETE : ROI_median negatif, drawdown excessif, hit_rate insuffisant ou taux reel incoherent.
ND : sample_n <10 ou calibration absente.

Regles :
- statut_segment_SP UTILISABLE : SP reel possible si autres criteres passent ;
- statut_segment_SP FRAGILE : micro-SP 1 EUR ou simulation ;
- statut_segment_SP REJETE ou ND : aucun SP reel strict ;
- sp_calibration_segments absent : SP standard interdit ;
- SP visible sans calibration = micro-SP ou simulation, pas edge net.

14. GRILLE PROBA_BASSE TECHNIQUE
La proba_basse ne doit pas etre inventee.
Elle doit etre associee a un score profil.

Score :
+1 forme recente propre
+1 3DERMUS 3-13
+1 J/E >=0
+1 aptitude/configuration prouvee
+1 marche stable ou steam coherent
-1 faute recente lourde
-1 rentree ou dependance au parcours parfait
-2 fautif chronique
kill-switch favori sous-paye fragile

Lecture brute :
score <=1 : proba_basse non defendable
score 2 : simulation ou micro
score 3 : CP_SEC ou SP possible
score >=4 : CP3 possible sous reserve proxy et CP_SEC non superieur

La grille donne une classe de proba_basse, pas une probabilite libre.

15. CALIBRATION DE PROBA_BASSE
Chaque classe de score doit etre calibree par resultats reels.

Table de calibration :
score_total, decisions, taux_top3_reel, taux_top4_reel, taux_faute, ROI_CP_SEC, ROI_CP3, ratio_median_CP_SEC, ratio_median_CP3, drawdown_max, statut_score, split, calibration_version, leakage_check_ok.

Statuts :
UTILISABLE : decisions >=30, taux reel coherent, ROI non negatif, drawdown acceptable.
FRAGILE : decisions 10 a 29 ou variance elevee.
REJETE : ROI negatif, drawdown excessif ou taux reel inferieur au seuil.
ND : moins de 10 decisions.

Regle :
- score UTILISABLE : proba_basse defendable si seuil economique passe ;
- score FRAGILE : simulation, micro ou mise minimale ;
- score REJETE/ND : aucun ticket reel strict.

16. VOLATILITE MARCHE SG
La volatilite SG controle la fiabilite du snapshot.
Elle ne selectionne jamais un cheval.

Formule :
variation_pct = abs(SG_t2 - SG_t1) / SG_t1

Buckets :
0 a 10 % = STABLE
10 a 20 % = SURVEILLABLE
20 a 35 % = INSTABLE
Plus de 35 % = KILL_SWITCH sauf justification documentee

Application :
- STABLE : pas de malus ;
- SURVEILLABLE : verifier que le mouvement confirme un profil deja defendable ;
- INSTABLE : downgrade qualite ou simulation ;
- KILL_SWITCH : NO BET si le mouvement touche une base, un favori central, une paire CP ou un cheval cle.

Champs de sortie :
SG_H30, SG_H10, SG_H5, SG_T8, variation_pct_H30_H5, variation_pct_H5_T8, statut_marche, impact_marche.

Fonction standard :
classify_market_volatility(SG_t1, SG_t2)

18. MOTEUR DE DECISION REPRODUCTIBLE
Le moteur ne remplace pas l'analyse sportive. Il fixe la decision calculable et rejouable.

Contrat :
meme input_hash + meme ruleset_version + meme engine_version = meme verdict.

Si le verdict change :
- input_hash different ;
ou
- ruleset_version different ;
ou

La sortie moteur prime sur la narration.
Si le moteur est absent, incomplet ou non rejouable : edge fragile, simulation ou NO BET.

19. ARBITRAGE CP_SEC VS CP3
Pour chaque candidat CP3, tester aussi CP_SEC sur la meilleure paire pre-course.

Colonnes minimales :
decision_id, course_uid, snapshot_time, selection_CP_SEC, selection_CP3, P_event_market_CP_SEC, R_prudent_CP_SEC, proba_basse_CP_SEC, R_prudent_meilleure_paire_CP3, nb_paires_defendables, decision_GPI, retour_officiel_CP_SEC, retour_officiel_CP3, ROI_CP_SEC, ROI_CP3, ratio_CP_SEC, ratio_CP3, drawdown_CP_SEC, drawdown_CP3, cp3_remboursant_flag, CP_SEC_domine_oui_non, structure_retenue, cause_ecart, split, calibration_version, leakage_check_ok.

Objectif :
choisir la structure la moins dilutive, pas celle qui donne le plus de combinaisons.

CP_SEC domine si au moins deux conditions sont vraies :
1. ROI_backtest_CP_SEC >= ROI_backtest_CP3 ;
2. drawdown_CP_SEC < drawdown_CP3 ;
3. ratio_median_CP_SEC >= ratio_median_CP3 ;
4. taux_CP3_remboursant eleve ;
5. une seule paire CP3 concentre l'essentiel de la probabilite ;
6. deux paires CP3 ont R_prudent <3,00 ;
7. segment CP3 ORANGE alors que la paire CP_SEC est VERT ou mieux couverte.

Si CP_SEC domine : CP3 refuse.
Si CP3 bat CP_SEC uniquement par un gros retour isole : CP3 simulation.
Si CP3 bat CP_SEC en ROI median, ratio median et drawdown acceptable : CP3 autorise sur ce segment uniquement.

20. FORMULES FINANCIERES
Mise totale = somme engagee.
Retour brut = somme payee par ZEturf.
Gain net = Retour - Mise.
ROI = (Retour - Mise) / Mise.
Ratio retour = Retour / Mise.
Ticket ratio 1,20 si Retour / Mise >=1,20.

CP3 ROI =
(retour des paires gagnantes - mise totale CP3) / mise totale CP3.

CP3_remboursant_flag =
vrai si 0,90 <= ratio_retour <= 1,20.

Edge reel =
taux_reussite_reel - break_even.

Drawdown max =
plus forte baisse de bankroll cumulee.

ROI median =
mediane des ROI tickets du segment.

21. COUT MARGINAL ET CORRELATION TACTIQUE
Une combinaison ajoutee doit ameliorer la couverture ou l'EV prudente.
Sinon elle dilue le ticket.

Pour chaque ajout :
cout_marginal
R_prudent_marginal
probabilite_evenement_marginale
scenario_couvert
risque_correlation
impact_ratio_minimal
impact_drawdown

Regles :
- ajout sans scenario distinct = refus ;
- ajout pour completer un pronostic = refus ;
- ajout qui transforme un CP_SEC dominant en CP3 dilutif = refus ;
- deux combinaisons dependantes du meme favori fragile = refus ;
- retour probable seulement remboursant = edge absent ;
- cout marginal > couverture prudente = NO BET ou structure plus simple.

Score correlation tactique :
0 = profils independants
1 = correlation faible
2 = correlation moyenne
3 = correlation forte, panier refuse

Facteurs :
meme style de course, meme dependance au train, meme risque de faute, meme position defavorable, meme besoin de parcours cache, meme dependance au favori fragile, meme scenario tactique obligatoire.

27. PHRASE SOURCE
Un proxy n'est utile que s'il est conservateur, audite hors echantillon et rejouable. Un segment qui surestime regulierement les rapports fabrique de faux edges. Sans decision_engine_outputs, split valide, proxy_error_by_segment, test CP_SEC vs CP3 et 50 decisions paper trading, le CP/CP3 reste simulation ou edge fragile. Sans sp_calibration_segments UTILISABLE, le SP standard est interdit.
