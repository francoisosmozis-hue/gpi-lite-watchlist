5. DEDOUBLONNAGE
Cle primaire course : date_course + hippodrome + nom_course. Si contenu identique : conserver un seul fichier. Si divergence : statut CONFLIT ; aucune course en conflit non resolu n'alimente C_prudent. Hash obligatoire.

6. CALCUL MARCHE
Pour chaque partant reel : q_i = 1 / SG_i ; M = somme(q_i) sur partants reels hors NP ; p_i = q_i / M. NP retires avant normalisation. Disqualifies conserves comme partants reels. P_event_market par Harville / Plackett-Luce.

Controle : toute normalisation realisee avec partants declares au lieu de partants reels est invalide. Tout calcul sans source_snapshot_time est exclu du strict.

7. EVENEMENTS CP
Chaque course >=8 partants genere les paires officielles top3 : 1-2, 1-3, 2-3. Pour chaque paire : P_pair_top3 ; C_observe_CP = rapport_CP_officiel x P_pair_top3. Le CP3 est un panier ; son ROI se calcule sur mise totale.

8. EVENEMENTS 2SUR4
Chaque course >=10 partants genere 6 paires top4 : 1-2, 1-3, 1-4, 2-3, 2-4, 3-4. C_observe_2sur4 = rapport_2sur4_officiel x P_pair_top4.

9. EVENEMENTS SP
Chaque partant avec SP_min visible peut generer un event_sp. Le resultat place depend du nombre de partants reels : top 2 paye de 4 a 7 partants ; top 3 paye a partir de 8 partants.

Tranches SP obligatoires :
SP_1_20_1_80 ; SP_2_00_2_90 ; SP_3_00_5_00 ; SP_SUP_5_00.

Regle : le SP ne se calibre jamais via le proxy CP. Il doit etre evalue par tranche_SP, discipline, bucket_N, rang_marche_bucket et score_bucket.

10. COEFFICIENTS CP/2SUR4
C_prudent = q25 si sample_n >=30 ; si 10-29 = min(q25 disponible, mediane*0,85) ; si <10 = ND. R_prudent = C_prudent / P_event_market. Standard reel : sample_n >=50. Robuste : sample_n >=100. Segment degrade si taux de surestimation proxy trop eleve, meme avec sample_n >=50.

11. STATUTS SEGMENTAIRES PROXY
Statut | Conditions | Usage
VERT | sample_n >=50 ; taux_surestimation <=35 % ; erreur_relative_mediane >=0 | Decision standard possible si autres criteres OK
ORANGE | sample_n >=50 ; taux_surestimation 35-45 % ou erreur_relative_mediane entre -10 % et 0 % | Edge fragile ; CP_SEC prioritaire ; CP3 tres limite
ROUGE | taux_surestimation >45 % ou erreur_relative_mediane < -10 % | Segment degrade ; CP/CP3 reel interdit
FRAGILE | sample_n 10-49 | Simulation ou exception documentee ; jamais edge net
ND | sample_n <10 ; proxy absent ; fallback non declare | Aucun ticket reel

Un segment ROUGE est exclu de toute decision reelle stricte. Un segment ORANGE doit etre signale dans la sortie et ne peut pas justifier un CP3 sans marge forte.

12. STATUTS SEGMENTAIRES SP
Statut | Conditions | Usage
UTILISABLE | sample_n >=30 ; ROI_median >=0 ; ratio_median acceptable ; drawdown_max acceptable | SP reel possible si SP_min, proba_basse et faits independants passent
FRAGILE | sample_n 10-29 ou variance elevee | micro-SP 1 EUR ou simulation uniquement
REJETE | ROI_median negatif, drawdown excessif, hit_rate insuffisant ou taux reel incoherent | SP reel interdit
ND | sample_n <10 ou calibration absente | SP reel interdit

Le seuil theorique proba_basse > 1,20 / SP_min reste necessaire mais insuffisant. La calibration SP par segment decide si un SP peut etre autre chose qu'une simulation ou un micro-SP.

13. FALLBACK
Exact : type+N+marche+selection+rangs+discipline. Puis : type+N+marche+selection -> type+N+marche -> type+N -> type global -> ND. Tout fallback doit etre trace dans le ticket. Fallback non declare = ticket reel interdit.

Fallback parent = edge fragile par defaut, meme si sample_n parent est eleve. Un fallback ne doit jamais masquer une absence de segment comparable.

14. MOTEUR DE DECISION REPRODUCTIBLE
Toute decision GPI pre-course doit produire une ligne decision_engine_outputs.

Contrat :
- Meme input_hash + meme ruleset_version + meme engine_version = meme verdict.
- Si le verdict change, il faut une nouvelle ruleset_version ou un nouvel input_hash.
- La sortie moteur prime sur l'analyse narrative.
- Si input_hash, P_event_market, proxy_status, score_total, statut_score ou CP_SEC_domine sont ND, la decision stricte est interdite.
- Toute sortie doit inclure reason_codes et kill_switch_codes.

Reason_codes standards :
PROXY_VERT ; PROXY_ORANGE ; PROXY_ROUGE ; PROXY_ND ; FALLBACK_PARENT ; FALLBACK_ND ; CP_SEC_DOMINE ; CP3_ONE_PAIR_ONLY ; CP3_TWO_WEAK_PAIRS ; SP_MIN_ABSENT ; SP_SEGMENT_ND ; SP_SEGMENT_REJETE ; SCORE_UTILISABLE ; SCORE_FRAGILE ; SCORE_REJETE ; SCORE_ND ; VOLATILITE_STABLE ; VOLATILITE_INSTABLE ; VOLATILITE_KILL_SWITCH ; NP_STATUS_INCERTAIN ; SG_INCOHERENTE ; QUALITE_D ; NO_BET_DEFAULT.

Controle replay :
output_replayed_oui_non et replay_match_oui_non doivent etre renseignes lors des audits. Si replay_match_oui_non = non, la decision est exclue du KPI strict jusqu'a correction.

Interdictions :

- valider CP3 sur un gros retour isole ;

- utiliser une ligne avec leakage_check_ok = false dans un KPI strict ;

18. BACKTEST CP_SEC VS CP3
Obligatoire avant conservation d'un CP3 reel. Pour chaque decision candidate CP3, conserver la meilleure paire CP_SEC pre-course et comparer : ROI, ratio median, drawdown, taux de remboursement, cause d'ecart.

CP_SEC domine si au moins deux conditions sont vraies : ROI_CP_SEC >= ROI_CP3 ; drawdown_CP_SEC < drawdown_CP3 ; ratio_median_CP_SEC >= ratio_median_CP3 ; CP3 remboursant frequent ; une seule paire CP3 concentre l'essentiel de la probabilite ; deux paires CP3 ont R_prudent <3,00.

Si CP_SEC domine : CP3 refuse. Si CP3 gagne uniquement par un gros retour isole : CP3 reste simulation. Si CP3 bat CP_SEC en ROI median, ratio median et drawdown acceptable : CP3 peut etre autorise sur ce segment uniquement.

19. CALIBRATION SP INDEPENDANTE
Le SP est une structure distincte du CP, du CP3 et du 2sur4. Il exige une calibration separee.

Conditions minimales pour etudier un SP standard :
- SP_min visible dans ZEturf ;
- SP_min rattache a snapshot_time ;
- top_paid_places calcule selon partants reels ;
- segment_sp_id renseigne ;
- statut_segment_SP = UTILISABLE ;
- proba_basse > 1,20 / SP_min ;
- au moins 3 faits independants ;
- aucun kill-switch.

Si statut_segment_SP = FRAGILE : micro-SP 1 EUR ou simulation.
Si statut_segment_SP = REJETE ou ND : aucun SP reel strict.
Si sp_calibration_segments absent : SP standard interdit, micro-SP seulement si profil tres propre et suivi separe.

21. VOLATILITE MARCHE SG
La volatilite SG devient une table de controle, pas un signal de pari automatique. Elle sert a detecter un marche instable qui peut invalider une decision CP/SP.

Calcul : variation_pct = abs(SG_t2 - SG_t1) / SG_t1.

Lectures minimales :
0 a 10 % : stable.
10 a 20 % : mouvement surveillable.
20 a 35 % : instable, downgrade de qualite ou simulation.
Plus de 35 % : kill-switch sauf justification forte et tracee.

Champs obligatoires : SG_H30, SG_H10, SG_H5, SG_T8 si disponibles ; variation_pct_H30_H5 ; variation_pct_H5_T8 ; statut_marche ; impact_marche.

22. CALIBRATION PROBA_BASSE
Le score proba_basse ne doit plus rester une grille qualitative. Chaque score doit etre compare aux resultats reels.

Pour chaque score_total et segment comparable, calculer : decisions ; taux_top3 ; taux_top4 ; taux_faute ; ROI_CP_SEC ; ROI_CP3 ; ratio_median ; drawdown_max ; statut_score.

Statuts :
UTILISABLE : decisions >=30, ROI non negatif, drawdown acceptable, taux reel coherent avec le seuil.
FRAGILE : decisions 10 a 29 ou variance trop forte.
REJETE : ROI negatif, drawdown excessif, score non reproductible ou taux reel inferieur au seuil.
ND : moins de 10 decisions.

Si la classe de score est REJETEE ou ND, proba_basse_defendable = non.
